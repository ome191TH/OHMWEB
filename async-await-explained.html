1ปัญหา: JS มีพนักงานแค่คนเดียว

JavaScript ทำงานทีละอย่าง (single thread) — เหมือนร้านก๋วยเตี๋ยวที่มีพนักงานคนเดียว ถ้าเขายืนตายเงียบรอน้ำเดือด ทั้งร้านก็หยุดตาม ⬇️ กดทดลองเลย

00:00.0
นาฬิกา + จานหมุน (ขับเคลื่อนด้วย JS)
ถ้าหน้าเว็บค้าง → มันจะหยุดเดินด้วย

🧪 ทดลอง 2 แบบ:

กดปุ่มด้านบน แล้วเฝ้าดูนาฬิกา...
สังเกต: กดแบบ Sync → นาฬิกาหยุดเดิน จานหมุนตาย กดอะไรไม่ได้เลย
กดแบบ Async → รอแค่ "ฟังก์ชันนี้" นาฬิกายังเดิน หน้าเว็บยังลื่น 
// ❌ แบบ Sync: JS ยืนรอเอง ทั้งร้านหยุด
const start = Date.now()
while (Date.now() - start < 2000) { }  // วนลูปเปล่าๆ 2 วินาที 😵

// ✅ แบบ Async: เอาบัตรคิวไว้ ไปทำอย่างอื่นก่อน
await new Promise(r => setTimeout(r, 2000))  // รอ 2 วิ แบบสงเสีย

fetch() ไม่ได้ให้ข้อมูลเลย — มันให้ "ใบสัญญาว่าของจะมา" ก่อน สิ่งนั้นคือ Promise (ชี้ที่แถวไหนก็ได้ มันจะสว่างให้ดู)

🎫 บัตรคิวที่พนักงานยื่นให้

Promise
💬 "ไปทำอย่างอื่นก่อน เดี๋ยวเรียก"
→
หน้าเว็บส่วนอื่นยังใช้ได้ปกติ
🔔 เบอร์ถูกเรียก เอาบัตรไปแลกของจริง
→
await
🍜 ก๋วยเตี๋ยวถึงมือ
→
ข้อมูลจริง (data)
⚠️ ถ้า ไม่ใส่ await = ยืนถือบัตรคิวเฉยๆ ไม่มีวันได้ก๋วยเตี๋ยว → const data = response.json() ได้ Promise มาเฉยๆ พอไปใช้ data.message จะได้ undefined

🎬 ภาพเต็ม: สั่งกาแฟ 1 แก้ว ผ่านโค้ด

กดปุ่ม แล้วดูว่าแต่ละบรรทัดโค้ด กับสิ่งที่เกิดขึ้นจริงในร้าน คู่กันยังไง

⏳
await — ยืนรอ
ฟังก์ชันนี้หยุดรอ แต่หน้าเว็บไปทำอย่างอื่นได้สบาย
🔔

ได้ response = กล่องพัสดุที่ยังไม่เปิด

  // ← ได้กล่องพัสดุ (response)

3Fetch 2 รอบ = พัสดุ 2 ขั้น 📦

ทำไมต้อง await สองครั้ง? เพราะมันเป็นสองงานคนละเรื่อง: รอกล่องมาส่ง กับ เปิดกล่องอ่านของข้างใน — กดปุ่มเพื่อยิง API จริง (dog.ceo) แล้วดูทุกขั้นพร้อมเวลาจริง

✂️
await response.json()
เปิดกล่อง อ่านของข้างใน
🎁
data.message
หยิบ URL รูปออกจากกล่อง
🐶

แปะรูปขึ้นหน้าเว็บ
// console จะบันทึกทุกขั้นตอนพร้อมเวลาที่ใช้จริง...
async function loadDog() {
  btn.disabled = true                        // ติดป้าย "รอแปป"
  const response = await fetch(url)          // รอที่ 1: กล่องมาถึง
  if (!response.ok) console.error(response.status) // ตรวจกล่อง
  const data = await response.json()           // รอที่ 2: เปิดกล่อง
  img.src = data.message                     // ของจริงใช้งาน
  btn.disabled = false                       // เอาป้ายออก
}

4กติกา 3 ข้อ + กับดักที่เจอมาแล้ว

สรุปเป็นกฎเหล็กที่เอาไปใช้ได้ทันทีตอนเขียนโค้ดจริง

1
async คือป้าย, await คือจุดรอ
จะใช้ await ได้ ฟังก์ชันต้องติดป้าย async ไว้หน้าชื่อก่อน — ใส่ await โดยไม่มี async = พังทันที ส่วนมี async แต่ไม่มี await = ไม่พัง แค่ป้ายเกินความจำเป็น
2
await ใช้เฉพาะงานที่ "ใช้เวลา"
fetch, .json(), เรียก API = ใช้เวลา → ต้อง await | เปลี่ยนข้อความ ลบ element = เสร็จทันที → ไม่ต้อง
3
await หยุดแค่ "ฟังก์ชันของตัวเอง"
หน้าเว็บส่วนอื่นเดินต่อ — นั่นคือเหตุผลที่ปุ่มต้อง disabled ด้วยมือ กันคนกดรัวระหว่างโหลด

🪤 กับดัก: Property (คำนาม) vs Method (คำกริยา)

รูปความหมายตัวอย่างผล
ไม่มี ( )📦 กล่องข้อมูล เปิดดูได้เลยinput.value, img.src✅ ถูก
มี ( )⚡ คำสั่ง ให้ลงมือทำfetch(), createElement()✅ ถูก
input.value()สั่ง "value" ให้ทำงาน?value ไม่ใช่ฟังก์ชัน!💥 พัง
img.scr = ...พิมพ์ผิด src → scrJS เงียบ สร้างกล่องใหม่เฉยๆ👻 bug เงียบ
💡 นิสัยที่ต้องฝึก: เปิด F12 → Console ทิ้งไว้ตลอด — bug เงียบพวกนี้มี error แดงๆ บอกเสมอ ถ้ารู้จุดที่ต้องมอง

5ทบทวน — คำถามที่ Mentor เค้าชอบถาม 😏

กดที่คำถามเพื่อเปิดเฉลย (ลองตอบในใจก่อนเปิดนะ — สมองจำได้ดีกว่าดูเฉลยเลย)

1. ถ้าเขียน const data = response.json() (ไม่มี await) — data จะเก็บอะไรไว้?▾
ได้ ใบบัตรคิว (Promise) มาเฉยๆ ไม่ใช่ข้อมูลจริง — พอเอาไปใช้ data.message จะได้ undefined เงียบๆ ทดลองได้: console.log(data) จะเห็น Promise {'{ }'}
2. มี async แต่ไม่มี await เลยในนั้น — จะเกิดอะไรขึ้น?▾
ไม่เกิดอะไรเลย ไม่ error — ฟังก์ชันวิ่งจนจบตามปกติ แค่ป้าย async เกินความจำเป็น (เหมือนติดป้าย "ร้านนี้มีที่จอง" ทั้งที่ไม่มีใครต้องรอ)
3. ทำไมต้อง await สองรอบ — รอ fetch กับรอ .json()?▾
เพราะเป็นงานคนละชิ้น: รอที่ 1 = รอกล่องพัสดุมาถึงหน้าบ้าน (ได้ response ที่ยังไม่เปิด) / รอที่ 2 = เปิดกล่องแล้วอ่านของข้างใน (ได้ data) — การเปิดกล่องก็ใช้เวลา ก็เลยแจกบัตรคิวมาเป็นของตัวเองอีกใบ
4. await หยุดหน้าเว็บทั้งหน้าใช่ไหม?▾
ไม่ใช่! await หยุดแค่ฟังก์ชันที่มันอยู่ — ส่วนอื่นของหน้าเว็บ (เลื่อน กด นาฬิกา) ยังทำงานได้ปกติ ...กลับไปกดปุ่ม ❄️ สีแดงในหัวข้อ 1 แล้วเทียบกับปุ่มเขียวดูสิ
